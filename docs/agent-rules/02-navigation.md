# 02 — Navigation (Expo Router) (MANDATORY)

**Scope:** Routes, typed hrefs, params, the Stack, module routes, modals, guards, and deep linking in Hive (Expo Router ~58, typed routes on, routes in `src/app`, iOS + Android only). Route-file essentials: [src/app/AGENTS.md](../../src/app/AGENTS.md).

## Non-negotiables

- [ ] Every file in `src/app/` is a route. Routes are thin: read params, set screen options, render a screen from `src/modules/<id>/screens/` or `src/screens/`.
- [ ] Typed routes: no untyped string hrefs, no relative hrefs; dynamic routes use `{ pathname, params }`. (TS)
- [ ] Router APIs come from `expo-router` only — never `@react-navigation/*` directly.
- [ ] The root navigator is a plain `<Stack />` in `src/app/_layout.tsx`. No tabs: Home is the launcher, and each module is a folder of routes `src/app/<id>/` pushed onto the Stack.
- [ ] Params are small strings — pass an id and refetch, never objects or entities.
- [ ] `useLocalSearchParams` by default; `useGlobalSearchParams` only with a written justification.
- [ ] Auth/visibility gating happens in layouts (`Stack.Protected` / `Redirect`), never `useEffect` + `router.push` in screens.
- [ ] Never name params `screen`, `params`, `initial`, or `state` (reserved).

---

## 1. File-based routing conventions (`src/app/`)

Standard Expo Router notation (`[id].tsx`, `[...rest].tsx`, `(group)/`, `_layout.tsx`, `+not-found.tsx`) — see the versioned Expo Router docs. Hive specifics:

- Route files and `_layout.tsx` default-export their component (Expo Router requires it; lint allows default exports only in `src/app/**`).
- `+api.ts` files are server routes ([01 §6](01-architecture.md#6-server-api-routes-srcappapiapits)). Other `+` files (`+html`, `+native-intent`, `+middleware`) are created only deliberately.
- Declare a screen only once per navigator — duplicate `<Stack.Screen name>` entries are invalid. Avoid reserved paths (e.g. `/assets`).
- Platform route variants need a universal file ([01 §7](01-architecture.md#7-platform-specific-code)).
- Module routes: `src/app/<id>/index.tsx` (the module's entry, linked from its Home card) and `src/app/<id>/<screen>.tsx`, each rendering a screen from `@/modules/<id>/screens/<screen>`. Generated by `pnpm new:module` / `pnpm new:screen <id>/<screen>`.
- Thin route shape: copy [src/app/settings.tsx](../../src/app/settings.tsx) (or [src/app/index.tsx](../../src/app/index.tsx) for a header-less screen). With params:

```tsx
// ✅ src/app/users/[id].tsx
export default function UserRoute() {
  const { id } = useLocalSearchParams<{ id: string }>();
  return (
    <>
      <Stack.Screen options={{ title: 'Profile' }} />
      <UserProfile userId={id} />
    </>
  );
}

// ❌ data fetching, business logic, or >~20 lines of JSX in a route file
```

## 2. Typed routes — hrefs are type-checked

Enforced by TypeScript (`experiments.typedRoutes`). `expo-env.d.ts` is generated and git-ignored; keep it and `.expo/types/**` in `tsconfig.json` `include`. If typecheck fails on missing route types, run `npx expo customize tsconfig.json`.

```tsx
✅ <Link href={{ pathname: '/users/[id]', params: { id } }} />   // PREFER for dynamic routes
✅ <Link href={`/users/${id}`} />
❌ <Link href="/users/[id]" />          // unexpanded dynamic path
❌ <Link href="./sibling" />            // typed routes do NOT support relative paths
```

- To stay inside the current group/tab without relative paths, build the path from `useSegments()`: ``const [first] = useSegments(); <Link href={`/${first}/profile`} />``.
- A computed string may be cast (`('/users/' + id) as Href`) only after validation, and sparingly. Never navigate to a URL taken from a param ([13 §4](13-security.md)).

## 3. `Link` vs imperative `router`

- PREFER `<Link href>` for anything the user taps. To wrap a custom pressable use `asChild` (as Home's gear button does):

```tsx
<Link href="/settings" asChild>
  <Pressable role="button" aria-label="Settings" testID="home-settings">
    <HeaderIcon />
  </Pressable>
</Link>
```

- Home opens a module from its tile on a group card (`testID="home-open-<id>"`) or the Dock (`home-dock-<id>`) with `router.push(module.href)`; `href` comes from `src/modules/registry.ts`. A group of more than four apps also opens as a folder (`/group/[id]`) from the card's fourth spot; a tile there (`group-open-<id>`) closes the folder, then navigates (`router.dismiss()` + `router.navigate(href)`, so Back returns to Home). Inside a module, link with absolute paths (`/habits/month`).

- Imperative `router` / `useRouter()` only from event handlers. `router.navigate` is the default (pushes or unwinds); `push` always adds an entry; `replace` after login/delete; `setParams` updates params without navigating; `dismiss`/`dismissAll` close modals.
- `<Redirect href>` for render-time redirects. `Link prefetch` only for expensive targets (a prefetched screen can't use the imperative router or `setOptions` until focused).

## 4. Params — `useLocalSearchParams` vs `useGlobalSearchParams`

- `useLocalSearchParams` reflects _this_ screen and doesn't update while it is in the background — safe for fetching on back-navigation.
- `useGlobalSearchParams` re-renders every mounted background screen on every URL change — use only when a background screen must track the live URL, and comment why.
- Changing a route param (`[id]`) remounts the screen. Search params (`?tab=x`) are optional.
- Params arrive as `string` (`string[]` for catch-alls) — parse and validate yourself. Type them: `useLocalSearchParams<'/users/[id]', { tab?: string }>()`.

```tsx
// ✅ screen refetches by id (cache hit via TanStack Query)
router.push({ pathname: '/users/[id]', params: { id: user.id } });

// ❌
router.push({ pathname: '/users/[id]', params: { user: JSON.stringify(user) } });
```

## 5. Layouts and Stack

### Root layout (`src/app/_layout.tsx`)

- The app bootstrap: `GestureHandlerRootView` → `QueryClientProvider` → `ThemeProvider`, plus splash-screen control and `<StatusBar style="auto" />`. Keep this order; global providers go here and nowhere else. Its error-boundary exports are owned by [14 §1](14-errors-resilience.md).
- Before rendering it runs `useMigrations(getDb(), migrations)` and keeps the splash up until done; a migration error throws to the root ErrorBoundary ([07 §8](07-data-state.md)).
- It renders a plain `<Stack />`. Routes set their own options with `<Stack.Screen options />` (Home: `headerShown: false`; every other screen shows the native header with its title).

### No tabs

- Hive has no tab bar. Home (`/`) is the launcher; Settings (`/settings`) opens from Home's gear button. Add a nested `_layout.tsx` inside `src/app/<id>/` only when a module needs its own navigator options (e.g. a modal or an anchor, §6, §8).

### Screen options placement

- Static, navigator-level options (which screens exist, presentation, guards) → `<Stack.Screen name="…" options>` in the layout.
- Route-specific or param-dependent options (dynamic title) → `<Stack.Screen options />` inside the route file (§1).
- Never call `navigation.setOptions` from deep inside screen/component trees.

## 6. Modals

- A modal is a normal route whose `presentation` (`modal`, `formSheet`, `transparentModal`, `fullScreenModal`) is set in the parent Stack layout. `formSheet` on Android: max 3 `sheetAllowedDetents`, no header, no native grabber (`sheetGrabberVisible` is iOS-only). Exemplar: the group folder, a `transparentModal` that draws its own backdrop — options in [src/screens/group-folder/folder-options.ts](../../src/screens/group-folder/folder-options.ts), registered in `src/app/_layout.tsx`. Customize Home is a `fullScreenModal` (Android falls back to `modal`) with its own title and Done — options in [src/screens/customize/customize-options.ts](../../src/screens/customize/customize-options.ts); it saves every edit at once, so leaving it never loses work.
- To open a regular screen from a modal, dismiss the modal first (`router.dismiss()`, then `router.navigate(href)`); a screen pushed on top of a modal is presented inside it on iOS.
- Deep-linked modals need an anchor so a screen exists behind them: `export const unstable_settings = { anchor: 'index' };` in the stack's `_layout.tsx`.
- RN `Modal` only for self-contained confirmations that should not be part of the URL.

## 7. Guards and redirects in layouts

```tsx
<Stack>
  <Stack.Protected guard={!!session} redirectTo="/sign-in">
    <Stack.Screen name="(app)" />
  </Stack.Protected>
  <Stack.Protected guard={!session}>
    <Stack.Screen name="sign-in" />
  </Stack.Protected>
</Stack>
```

- Guards nest (`isLoggedIn` → `isAdmin`); when a guard flips to false its history entries are removed.
- Keep the splash screen up until async auth state loads, so guards don't flicker.
- Route protection is client-side only — NOT security. Enforce access in `+api.ts` ([13 §5](13-security.md)).

## 8. Deep linking

- Every route is deep-linkable. The scheme comes from the `APP_VARIANT` config in `app.config.ts`: `hive://`, `hive-preview://`, `hive-dev://` (e.g. `hive://habits/month`). Assume any screen can be the entry point: params serializable, screens self-load from params.
- Missing back button on a deep link ⇒ missing `unstable_settings.anchor` in that stack's layout. Use `<Link withAnchor>` when jumping into another stack.
- Remap third-party/legacy URL shapes in `+native-intent.tsx` — no URL parsing in screens. Treat every incoming param as untrusted ([13 §4](13-security.md)).
- Universal/App Links (`ios.associatedDomains`, `android.intentFilters`) are `app.config.ts` changes ⇒ store release ([01 §4](01-architecture.md#4-cng--native-projects-are-generated-never-edited)).

## Common agent mistakes

1. Fat route files: fetching, logic, and full JSX in `src/app/*.tsx` instead of a module or shell screen component.
2. Importing from `@react-navigation/*` directly.
3. Passing objects/JSON through params instead of ids; forgetting params are always strings.
4. `useGlobalSearchParams` by default — background re-renders across the stack.
5. Guarding auth with `useEffect` + `router.push` in screens; treating route guards as security.
6. Adding a tab bar, or a module route that is not reachable from its Home card.
7. Hand-writing a module's route folder instead of `pnpm new:module` / `pnpm new:screen <id>/<name>`.
8. Modals without an anchor.
