# .maestro — E2E flows

- One top-level YAML per user journey (`smoke.yaml`, `create-thing.yaml`); header `appId: com.ruvceski.hive.dev` — flows run against an installed dev build (`pnpm test:e2e`).
- Each module has `<id>.yaml` (generated by `pnpm new:module`, tagged with the id) that starts at Home and opens the module with `tapOn: { id: 'home-open-<id>' }`. Module screens are wired into navigation from day one, so new flows don't need the `wip` tag; `config.yaml` still excludes `wip` for flows that are knowingly unfinished.
- Reusable steps go in `subflows/` and are called with `runFlow` (parameterize with `env`). `config.yaml` only discovers top-level files, so subflows never run standalone.
- Select by `id:` (the element's `testID`) first; text selectors only when the text itself is the behavior under test.
- Never sleep. Rely on `assertVisible`'s retry or `extendedWaitUntil` with a `timeout:`.
- Tag flows (`tags: [smoke]`) and keep `config.yaml` include/exclude rules in sync when adding tags or folders.
- Screenshot baselines (`*.png`) are test oracles: only the user records or updates them.
