# src/screens — shell screens

Only the shell's own screens live here: Home (the module launcher), the group folder, Customize Home and Settings. Module screens live in `src/modules/<id>/screens/` ([src/modules/AGENTS.md](../modules/AGENTS.md)). One folder per screen: `<name>/index.tsx` exports the screen (named export), private pieces in `<name>/components/`. New shell screen: `pnpm new:screen <name>` (screen + test + route), then link to it.

- **Design first.** Each shell screen has an approved reference in [docs/design/](../../docs/design/README.md) (Home, Settings, Customize, group folder, empty state; dark and light). Implement from it, not from memory or the canvas.
- **Never import another screen or a module's internals.** Shell screens may import `@/modules/registry`. When a second screen needs a component, promote it to `src/components/`. Lint blocks upward imports (screens → app); screen-to-screen imports are caught in review.
- **Data.** Screen-local TanStack Query hooks live next to the screen as `use-<thing>.ts`, with a key factory and a shared `queryOptions`: local SQLite via `getDb()` — copy `@/hooks/use-home-layout` (an optimistic mutation: `@/hooks/use-app-settings`); remote via `api<T>()` — copy `settings/use-health.ts`. App-wide data that the root layout or several screens need (Settings preferences; Home's layout and app usage, read by Home, the group folder and Customize) lives in `src/hooks/` instead — a screen can't import another screen (`@/hooks/use-app-settings`). Hooks may not import `@/modules`, so a hook that needs the registry takes it as an argument (`useEditHome(hiveModules, defaultHomeGroups)`). Pure logic goes in a React-free file with tests (`@/utils/home-groups`, `@/utils/home-edits`). Rules: [07-data-state.md](../../docs/agent-rules/07-data-state.md).
- **Four states, always.** Loading → `LoadingState`, error → `ErrorState` wired to `refetch`, no data → `EmptyState`, then success. If cached data exists, keep showing it when a background refetch fails ([07 §1](../../docs/agent-rules/07-data-state.md), [14 §3](../../docs/agent-rules/14-errors-resilience.md)).
- **Layout.** `ThemedView`/`ThemedText` + tokens, safe-area insets (Home has no header, so it uses `SafeAreaView`), content capped at `MaxContentWidth`, works in light and dark mode ([03](../../docs/agent-rules/03-ui-design-system.md), [04](../../docs/agent-rules/04-responsive-adaptive.md)).
- **Tests** are colocated (`index.test.tsx`), `await render(...)`, `userEvent` for interaction. SQLite-backed hooks are mocked (`jest.mock('@/hooks/use-home-layout')` — copy `home/index.test.tsx`); remote screens use a fresh `QueryClient` with `{ retry: false, gcTime: Infinity }` and `@/lib/api` mocked, waiting for the _value_ (`waitFor`) — copy `settings/index.test.tsx` ([09](../../docs/agent-rules/09-testing.md)).
- A new user-visible screen or flow also gets a Maestro flow in `.maestro/`.
